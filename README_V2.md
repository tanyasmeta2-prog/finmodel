# Конфигуратор — Версия 2

Обновление 26.11.2026. Рабочая ветка `configurator-v2`, файл запуска `app.py`.
Исходная ветка `main` сохраняется отдельно.

## Реализованные изменения по макетам

- Площади квартир, коммерции, кладовых и участка вводятся на вкладке «Блоки»; в СМР подставляются автоматически.
- «СМР → Объёмы» содержит только объёмы и ручные уточнения элементов. Ставки вводятся в «Коробка A–E»; аналог и дата цен не требуются.
- Каждый вариант отделки фасада добавляется отдельной строкой ТИП 1, ТИП 2 и далее. У каждой строки собственные стабильный ID, уточнение, объём, ставка и статус; в ставки попадают введённые на вкладке объёмов элементы.
- B20.10: укрупнённый режим = общая площадь фасада × комплексная ставка; детальный = сумма рассчитанных элементов. Режимы взаимоисключающие. Без разбивки используется укрупнённый режим. Статусы: «Рассчитан / Не требуется / Нет данных»; неполная сумма отмечается явно, без автоматической доплаты по общей площади фасада.
- ИТП / котельная — единая строка общей таблицы объёмов, выбор в колонке «Ед.», комплект на этап. Отдельно от инженерных ставок, без переключателя исключения повторного начисления. Пояснение состава — в необязательных комментариях раздела D «Инженерия».
- Все основные статьи обязательны: отдельной применимости нет. Комментарии «Уточнение границ состава ставки» необязательны.
- ✎ — редактируется, 🔒 — только просмотр. Таблицы с ручным вводом светло-жёлтые, без ручного ввода серые; цвета не зависят от роли сотрудника.

## Методика

- МП: A10/B30 — застройка, A20 — застройка секций, B10 — надземная площадь, B20 — фасад (высота этажа 3,0 м, сблокированные торцы исключаются), E20 — секции. Остальные статьи по NSA. Стилобат — отдельная непересекающаяся строка.
- ЭП: наружные конструкции по базам СЭО — фасады и кладка м², ограждения м², корзины и экраны шт., входные группы м² отделки или отдельные группы без площади шт., террасы м². Двери квартир — по числу квартир, двери МОП — по проёмам. Мебель МОП — по площади холлов.
- Ставки МП и ЭП раздельны. Сценарный коэффициент применяется один раз к базовой сумме.
- **G, Z, паркинги, инфраструктура и распределение косвенных расходов сохраняют действующие формулы.** Новые базы наружных работ и правила исключения площадей не внедрены: ожидается уточнение со сметчиками.

## Excel

- «Бюджет по статьям»: единый список кодов слева; справа УБ через пустой разделитель. Детальные колонки каждого УБ сворачиваются через +/− до «Сумма». Включены G, Z, генподряд и инфраструктура; состав ставки берётся из комментариев.
- «Элементы B20.10»: УБ списком, внутри каждого элементы списком; разделитель между блоками. Все УБ первоначально свёрнуты до B20.10 с общей суммой; +/− раскрывает детали и статусы.
- «Косвенные»: все исходные статьи земли, благоустройства, инфраструктуры и прочих разделов, итоги и распределение на УБ. «Инфраструктура — состав» сохраняет свободные статьи по блокам.
- «Блоки» — общие площади и параметры, без отдельных колонок ИТП и котельной.
- Формульные вспомогательные листы сохранены и скрыты. Шаблон ввода отдельно сохраняет геометрию, обе стадии ставок, элементы с ID, режимы B20.10 и выбор ИТП/котельной.
- Данные из демонстрационных макетов в модель не добавляются.

## Совместимость и сохранение

Прежние ставки с изменёнными единицами архивируются. Если старый проект содержит одновременно ИТП и котельную, перенос сопровождается предупреждением и требует выбора одного варианта; двойного начисления нет.
Сохраняются существующие пути Версии 2 (`talan_model_saves_v2`, `talan_model_last_opened_v2.json`, `app:/projects_v2`). Новая система сохранности проектов в объём обновления не входит.

## Проверка и запуск

```bash
pip install -r requirements.txt
pip install pytest
python -m pytest tests/test_methodology_v2.py -q
streamlit run app.py
```

Тесты проверяют расчёт МП/ЭП, взаимоисключение режимов и неполноту B20.10, стабильность типов/ID, перенос ИТП, применение сценария, импорт/экспорт, группировку нескольких УБ и неизменность численного кода G/Z, паркингов и инфраструктуры относительно базовой Версии 2.
